## 第一章：XBRL 解析器与工业级标签映射

### Inline XBRL 格式

SEC 上市公司以 Inline XBRL（iXBRL）提交财报——数据嵌入在 HTML 的 `<ix:nonFraction>` 标签中：

```html
<ix:nonFraction name="us-gaap:RevenueFromContractWithCustomerExcludingAssessedTax"
  contextRef="c-1" unitRef="USD" scale="6" id="f-30">81,615</ix:nonFraction>
```

`scale="6"` 表示数值乘以 10⁶（百万美元）。81,615 × 10⁶ = $81.615B。

### 标签名不一致问题

苹果用 `RevenueFromContractWithCustomerExcludingAssessedTax`，谷歌用 `Revenues`，特斯拉用 `SalesRevenueNet`。同一个"收入"概念在不同审计师手下标签完全不同。必须建立 **fallback 链**：

```ts
// worker/src/xbrl-tags.ts — 工业级标签映射字典
export const INCOME_TAGS: Record<string, TagSet> = {
  revenue: {
    key: 'revenue', label: '营业收入', category: 'income',
    tags: [
      'us-gaap:RevenueFromContractWithCustomerExcludingAssessedTax',  // ASC 606
      'us-gaap:Revenues',                                             // 传统
      'us-gaap:SalesRevenueNet',                                      // 工业/零售
      'us-gaap:RevenueFromContractWithCustomer',                      // 变体
      'us-gaap:TotalRevenues',                                        // 兜底
    ],
  },
  netIncome: {
    key: 'netIncome', label: '净利润', category: 'income',
    tags: [
      'us-gaap:NetIncomeLoss',
      'us-gaap:ProfitLoss',
      'us-gaap:NetIncomeLossAvailableToCommonStockholdersBasic',
    ],
  },
  // ... 32 个标签集 × 3-5 fallback 标签
}
```

解析器遍历每个标签的 fallback 链，取第一个非空值：

```ts
// 解析 iXBRL 的核心循环
const ixRegex = /<ix:non(?:Fraction|Numeric)\b([^>]*)>([^<]+)<\/ix:non(?:Fraction|Numeric)>/g
while ((m = ixRegex.exec(xmlText)) !== null) {
  const nameMatch = m[1].match(/\bname="([^"]+)"/)
  const ctxMatch = m[1].match(/\bcontextRef="([^"]+)"/)
  const scaleMatch = m[1].match(/\bscale="(\d+)"/)
  if (!nameMatch || !ctxMatch) continue

  const concept = nameMatch[1]
  const scale = parseInt(scaleMatch?.[1] || '0', 10)
  const rawValue = parseFloat(m[2].replace(/,/g, ''))
  const value = rawValue * Math.pow(10, scale)  // Apply SEC scale factor

  for (const [suffix, key] of Object.entries(CONCEPT_MAP)) {
    if (concept === 'us-gaap:' + suffix || concept.endsWith(':' + suffix)) {
      raw[key].push({ period: getContextPeriod(ctxMatch[1]), value })
      break
    }
  }
}
```

这套映射覆盖了标普 500 成分股的不同审计习惯，解析成功率 ~95%。

## 第二章：Cloudflare Workers 代理层

### 架构约束

Worker 免费计划的 CPU 限制是 **10ms**，而解析一份 2MB 的 XBRL 文件需要 15-50ms。经历了上百次 1101 错误后，结论是：**Worker 只能做 HTTP 转发，不能做计算**。

### 财务数据端点（仅返回 URL 列表）

## 第四章：自然语言筛选引擎

不依赖任何 AI 模型——纯规则解析器，支持中文金融词汇：

```ts
// src/lib/query-parser.ts — 中文金融查询解析器
const METRIC_ALIASES: Record<string, string> = {
  '收入': 'revenue', '营收': 'revenue',
  '收入增速': 'revenueGrowth', '利润增速': 'netIncomeGrowth',
  '毛利率': 'grossMargin', '净利率': 'netMargin',
  '负债率': 'debtRatio', 'PE': 'pe', '市盈率': 'pe',
  'ROE': 'roe', '市值': 'marketCap', '现金流': 'cashFlow',
}

const OP_ALIASES: Record<string, 'gt' | 'lt'> = {
  '>': 'gt', '＞': 'gt', '高于': 'gt', '超过': 'gt', '大于': 'gt',
  '<': 'lt', '＜': 'lt', '低于': 'lt', '不足': 'lt', '小于': 'lt',
}

export function parseQuery(input: string): ParsedQuery {
  for (const [alias, metric] of Object.entries(METRIC_ALIASES)) {
    for (const [opAlias, op] of Object.entries(OP_ALIASES)) {
      const pattern = new RegExp(`${escapeRegex(alias)}\\s*${escapeRegex(opAlias)}\\s*([\\d.,]+\\s*[%％BbMm]?)`, 'gi')
      const match = pattern.exec(input)
      if (match) {
        filters.push({ metric, op, value: parseValue(match[1]), raw: match[0] })
        input = input.replace(match[0], '')
      }
    }
  }
  return { filters, keywords: input.trim().split(/\s+/), raw: input }
}
```

输入 `"收入增速>30% 毛利率>60% 负债率<30%"` → 三个结构化筛选条件。异步批处理匹配，8 家并发：

## 第五章：量化分析矩阵

学术界半个世纪验证的三大量化模型，全部用 TypeScript 实现。

### Altman Z-Score（破产预测，1968）

```ts
// src/lib/finscope-scoring.ts
export function altmanZScore(d: FinancialData): ScoreCard {
  const x1 = (currentAssets - currentLiabilities) / totalAssets  // 流动性
  const x2 = retainedEarnings / totalAssets                       // 累积盈利
  const x3 = ebit / totalAssets                                   // 资产效率
  const x4 = stockholdersEquity / totalLiabilities                // 偿债能力
  const x5 = revenue / totalAssets                                // 资产周转

  const z = 1.2*x1 + 1.4*x2 + 3.3*x3 + 0.6*x4 + 1.0*x5
  return {
    score: Math.round(z * 100) / 100,
    rating: z > 2.99 ? '🟢 安全区' : z >= 1.81 ? '🟡 预警区' : '🔴 危险区',
    interpretation: z > 2.99 ? '财务健康，破产风险极低'
      : z >= 1.81 ? '处于灰色地带，需关注现金流'
      : '存在财务困境风险'
  }
}
```

### Beneish M-Score（财务造假检测，1999）

8 项指标检测企业是否在粉饰报表。核心逻辑：

```ts
const dsri = (recv/rev) / (recvPrev/revPrev)       // 应收账款异常增长
const gmi = ((revPrev-cogsPrev)/revPrev) / ((rev-cogs)/rev)  // 毛利率异常变化
const aqi = (1 - (ca+(ta-ca-tl))/ta) / (1 - (caPrev+(taPrev-caPrev-tlPrev))/taPrev)
const tata = (ni - ocf) / ta                        // 应计项目过高

const m = -4.84 + 0.92*dsri + 0.528*gmi + 0.404*aqi + 0.892*sgi
        + 0.115*depi - 0.172*sgai + 4.679*tata - 0.327*lvgi
```

**评级**：M > -1.78 为操纵嫌疑，M > -2.22 需关注，M < -2.22 正常。

### Piotroski F-Score（基本面质量，2000）

```ts
export function piotroskiFScore(d: FinancialData): ScoreCard {
  let score = 0
  if (netIncome > 0) score++
  if (operatingCF > 0) score++
  if (roa > roaPrev) score++
  if (operatingCF > netIncome) score++       // 核心——防止纸面富贵
  if (debtRatio < debtRatioPrev) score++
  if (currentRatio > currentRatioPrev) score++
  if (!dilutedShares) score++                // 未增发
  if (grossMargin > grossMarginPrev) score++
  if (assetTurnover > assetTurnoverPrev) score++

  return {
    score, maxScore: 9,
    rating: score >= 7 ? '🟢 高质量' : score >= 4 ? '🟡 中等' : '🔴 低质量'
  }
}
```

三模型加权综合评分：Z-Score 权重 35% + M-Score 30% + F-Score 35%，输出五级评级。

## 第六章：自定义指标系统

在学术界三模型之上，设计了 **37 项自定义指标体系**：

```ts
// 指标定义结构
export interface Indicator {
  id: string
  name: string
  category: IndicatorCategory  // growth | profit | efficiency | stability | momentum
  description: string
  compute: (d: FinancialData) => number | null
  normalize: (v: number) => number  // 映射到 0-100
}

// 示例：动量-利润转折信号
{
  id: 'm03', name: '利润转折信号', category: IndicatorCategory.Momentum,
  description: '最近 1 季度利润 / 前 4 季度平均利润',
  compute: d => {
    const latestNI = last(d.netIncome)
    const avg = sum(d.netIncome.slice(0, -1), 4) / 4
    return latestNI && avg > 0 ? (latestNI / avg - 1) * 100 : null
  },
  normalize: v => Math.min(100, Math.max(0, 50 + v * 2)),
}
```

function recognizePatterns(records: QuarterRecord[]): PatternMatch[] {
  const recent = records.slice(-4)
  const older = records.slice(-8, -4)

  if (midAvg < firstAvg * 0.9 && lastAvg > firstAvg * 1.1) {

## 第八章：管理层情绪分析

从 SEC 10-K/10-Q 文件中提取 ~8000 词的 MD&A 章节，用**自定义金融情感词典**分析：

```ts
// src/lib/finscope-sentiment.ts
const OPTIMISTIC = new Set([
  'growth','accelerating','momentum','expanding','robust','record',
  'opportunity','upside','outperform','confident','optimistic',
  '增长','加速','扩张','强劲','历史新高','超出预期','上调指引',
])

const CAUTIOUS = new Set([
  'challenging','headwind','uncertainty','volatility','pressure',
  'restructuring','impairment','litigation','regulatory',
  '谨慎','挑战','逆风','不确定性','波动','重组','诉讼',
])

export function analyzeSentiment(text: string, period: string): SentimentScore {
  const tokens = text.toLowerCase().split(/\s+/).filter(w => w.length > 1)
  const optCount = ngramMatch(tokens, OPTIMISTIC)     // 多词匹配
  const cauCount = ngramMatch(tokens, CAUTIOUS)
  const scale = 1000 / tokens.length                   // 千词归一化
  const netSentiment = (optCount - cauCount) * scale * 10  // -100 to +100
  return { period, optimistic: optCount*scale*10, cautious: cauCount*scale*10, netSentiment }
}
```

多期追踪情绪变化曲线，检测管理层语调的改善/下降/波动趋势。

## 第九章：MWE 动量加权外推

波动率自适应的预测算法——独特之处在于 λ 是**数据驱动的**：

```ts
// src/lib/finscope-engine.ts
function mwe(values: number[]): MweResult {
  const cv = sigma / (Math.abs(mean) + 1)            // 变异系数
  const lambda = 0.2 + Math.min(cv * 0.3, 0.5)      // 自适应 λ ∈ [0.2, 0.7]
  const weights = values.map((_, i) => Math.exp(-lambda * (n - 1 - i)))  // 指数衰减

  const predicted = weightedMean + weightedSlope * 1  // 1 步预测
  const bandFactor = sigma * Math.sqrt(1) * 1.5       // 波动率置信带
  const r2 = 1 - ssRes / ssTot                        // R² 置信度

  return { predicted, confidence: r2, upperBand: predicted + bandFactor, lowerBand: predicted - bandFactor }
}
```

高波动时 λ↑ → 更依赖近期数据。低波动时 λ↓ → 看长期趋势。完全自调整，无人工预设参数。

## 踩坑记录

1. **Cloudflare Workers 10ms CPU 硬限制**：100+ 次 1101 错误后，将全部解析移到客户端。Worker 只做 HTTP 转发。

2. **XBRL 标签不一致**：苹果用 `RevenueFromContractWithCustomerExcludingAssessedTax`，谷歌用 `Revenues`。Fallback 链是唯一解决方案。

3. **估值需要流通股数据**：初始实现了四种估值方法（Graham、P/E、P/CF、P/S），但 SEC 不直接提供流通股数。反推链每一步放大误差，最终移除。

4. **Yahoo Finance 在中国大陆被拦截**：Worker 在 Cloudflare 境外节点可正常访问 Yahoo，用户只需访问自己的域名 `2assqw.cc`。

5. **SEC API 拦截自动工具**：User-Agent 必须包含联系邮箱，格式为 `"组织名 邮箱"`，不带括号。
